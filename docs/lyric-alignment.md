# 算法智能对齐

全屏播放器歌词右侧的「算法智能对齐」可以将逐行主歌词与歌曲音频对齐为逐字时间，再将已有翻译与音译关联到该时间轴。声学推理、分词、读音匹配和语义推理由播放器自带的 **Rust 工作进程** 完成，无需安装 Python 或 PyTorch。

它只使用已有文本，不生成或改写歌词。主歌词声学对齐属于 Beta，低评分结果也会生成，并在预览中显示警告。AI 歌词翻译和模型配置是独立功能，见 [AI 歌词](/ai)。

## 主歌词转逐字

加载本地或已完整缓存并加载的音源，打开弹窗，勾选「主歌词转逐字」，选择汉语、日语或英语。声学与翻译模型统一在「设置 → 歌词设置 → 歌词对齐模型」中下载、校验和移除；未就绪时，对齐弹窗提供「去设置」入口。可以同时勾选已有翻译和音译：主歌词时间计算完成后，辅助轨道再依据新字词对齐，两个大型模型不会同时驻留。

中文按汉字、英文按词定位。日语复用 Lindera/IPADIC 与 WanaKana，保留无法可靠拆读的汉字词组，将促音、拗音和长音与相邻发音单元成组。原文、空格与标点保持不变，不用字数均分推算时间。整首主歌词均可处理，包括已有逐字时间；应用后替换所选行的原有时间。

算法使用固定版本 MMS_FA UINT8 ONNX 模型和包含空白、重复字符约束的 CTC Viterbi 搜索。沿用音频引擎的静态 FFmpeg 和容器输入视图，每次只解码一行的 16 kHz 单声道窗口。行级时间前后各保留 500 毫秒搜索余量，CUE 起点只用于音源定位，返回值仍是歌曲相对毫秒时间。

长行按约 20 秒分段推理，并保留上下文；CTC 使用检查点与分块回溯，不因超过 30 秒而跳过整行。整曲请求在内部按传输大小自动分批，用户只需开始一次，不需要手动拆分。背景声部不属于本次主歌词生成范围。

整行评分低于 0.35 或有字词评分低于 0.02 时仍返回候选，仅增加警告。未知读音和未展开的数字由声学通配符估算并标注，静音区间也返回低可信候选。评分不是正确率；拖音结束时间、强伴奏、合唱和估算读音可能产生明显错误。界面会提示试听检查，文件无法解码或时间本身无效时保留原内容并显示失败原因。

应用后通过现有 TTML 序列化更新内存歌词，重新解析和保存时保留时间轴；点击保存前不会修改歌曲或歌词文件。

### 模型与 AutoMix 复用

声学权重来自 [xycld/lyric-align-mms-fa](https://huggingface.co/xycld/lyric-align-mms-fa)，固定修订为 `06e6cbfa5c257d23981c922f6406f5def958eb95`，约 302 MiB。模型及作者说明存放于 `{userData}/app-data/runtimes/lyric-acoustic/model/`，逐文件检查长度和 SHA-256，并在真实推理成功后写入就绪标记。

权重继承 Meta 的 **CC-BY-NC-4.0 非商业许可**，不随播放器分发。界面下载说明和随代码保留的模型声明均列出来源与许可；商业使用需另行取得授权。

声学推理复用 AutoMix 已安装的 ONNX Runtime；缺少运行库时，显式准备声学模型会只安装运行库，不下载节拍或 Demucs 模型。移除声学模型不影响翻译模型或共用运行库。AutoMix 的节拍结果不含字音信息，不能直接转换为逐字时间。

已用现有 AutoMix Demucs 对少量唱句作分离对照：能提升部分英文唱句评分，但没有稳定恢复测试中的未匹配唱句，也不能解决行级时间截断起音。因此本版未将人声分离加入默认流程，仍保留后续按需接入的可能。

### 语言扩展

声学模型与 CTC 搜索共用，语言相关的原文到字音映射集中在 `native/lyric-alignment/src/acoustic/text.rs`。后续法语、德语、俄语需要在此补充规范化与读音规则，扩展共享语言类型及界面选项，并用对应语言的实录音频验证；当前不将未验证语言显示为已支持。

算法参考 [TorchAudio 多语言强制对齐说明](https://docs.pytorch.org/audio/stable/tutorials/forced_alignment_for_multilingual_data_tutorial.html)。与 Whisper 识别后文本匹配相比，这条路径直接使用现成歌词与声学概率，不先生成一份识别歌词。

## 使用方式

1. 加载具有真实逐字时间的主歌词，以及已有的翻译或音译
2. 打开「算法智能对齐」，选择翻译、音译或两者
3. 翻译首次使用时在「设置 → 歌词设置 → 歌词对齐模型」中下载翻译模型；只处理音译时无需下载
4. 点击「开始对齐」，检查逐行预览，并勾选希望应用的候选行
5. 点击「应用所选」立即更新歌词显示；需要写入文件时再显式保存歌词

默认保留已完整对齐的辅助轨道。「重新对齐已有逐字翻译和音译」允许重新计算上方选中的轨道；未选择、未匹配或未勾选的轨道保留原有内容。预览分别统计本次检查、匹配成功和已有对齐的数量。

仅选择辅助对齐时，只有整行时间、没有辅助文本或不足两个独立时间锚点的行不会生成辅助逐字候选。辅助轨道沿用原有匹配筛选；主歌词生成不按低评分跳过，应用前需检查预览。

## 音译匹配

- 日语通过 Lindera/IPADIC 获取词性、基本形和读音，使用原生 WanaKana 转换假名，再进行全局编辑距离及唯一读音锚点匹配
- 保留 IPADIC 的多读音顺序及同分优先级，支持已有注音、助词、长音、促音、转写体系差异和跨主歌词字词的整词读音
- 中文拼音通过多音字词典匹配，保留声调、大小写、标点和空白；不把 `u` 与 `ü` 混为一音
- 输出必须完整覆盖现成音译且满足评分要求，缺词、歧义或未知读音过多时保留原行

## 翻译匹配

翻译使用 Candle 在本机 CPU 运行固定的多语言 BERT，提取与原 SimAlign 相同的第八层词向量。Rust 实现余弦相似度、IterMax、子词与完整词候选、实词短语扩展和词典基本形候选，并保留原有候选优先级。

中文译文采用 ICU 同源词典和 ICU4C 的最小词频代价切分，避免更换分词实现后改变语义锚点。词对始终映射到主歌词原词范围；跨语言重排复用现有辅助时间轴顺排流程，不按译文字数制造时间。

翻译失败不会丢弃已经匹配成功的音译。相关错误可在弹窗中查看，原有翻译保持不变。

## 模型下载与移除

### 下载与存放位置

模型固定为 `google-bert/bert-base-multilingual-cased` 的 `3f076fdb1ab68d5b2880cb87a0886f315b8146f8` 版本，权重约 714 MB。下载遵循播放器代理设置，逐文件验证长度和 SHA-256；仅在原生推理验证成功后发布就绪标记。准备完成后的对齐完全离线执行。

打开弹窗或开始对齐不会自动下载。下载可取消、重试，关闭弹窗或主窗口后可继续后台运行；重新打开可恢复进度，明确退出播放器会取消并等待清理。

文件存放在 `{userData}/app-data/runtimes/lyric-alignment/`：

```text
lyric-alignment/
├── model/          # 固定版本的模型、分词器与许可证
└── ready.json      # 已通过原生推理的完成标记
```

设置中的模型下载或校验会先检查本地文件，完整文件直接复用，仅下载缺失或损坏的文件。验证失败可重试，已有完整模型文件不会重复下载。

### 移除模型

模型标记不绑定绝对目录或平台，便携版移动后无需重新下载模型。「移除模型」删除本功能的模型目录；移除后仍可使用音译，翻译需重新准备模型。对齐使用中、下载中或移除中会阻止并发操作。

## 资源与行为边界

- 同时只运行一个任务，每次任务独占 Rust 进程，结束或取消后回收词典、模型和计算线程
- 模型不常驻播放器主进程，计算不阻塞歌词动画与播放控制
- 单次原生请求的传输边界为 1,000 行、合计 64,000 个 UTF-16 代码单元，输入输出各不超过 1 MiB；整曲主歌词由界面内部自动分批
- 模型每侧最多 512 个子词，超长输入不接受截断后的伪完整结果
- 切歌、换源、修改歌词、关闭弹窗或取消任务会使旧结果失效
- 复用现有的辅助轨道开关、歌词窗口同步、TTML 和本地文件保存流程

原生工作进程与播放器一起构建，目标平台为 Windows、macOS、Linux 的 x64/ARM64。性能数据和实际验证范围见[原生对齐验证](/native#对齐验证)；模型文件本身与平台无关。
