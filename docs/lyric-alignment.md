# 本地歌词对齐

全屏播放器歌词右侧的「算法智能对齐」入口，可以把现成的翻译与音译关联到主歌词的逐字时间轴。整个过程不重新识别音频、不重新打轴、不生成或改写任何歌词文本：音译对齐完全在本地运行，翻译对齐使用应用内安装的独立本地 Python 环境。

需要生成缺失的翻译、音译，或调用配置的文本模型进行逐字对齐时，请使用 [AI 歌词翻译与生成](/ai)。本页介绍的本地对齐无需 AI 模型 API Key。

## 快速使用

1. 播放已有真实逐字主歌词，以及翻译或音译的歌曲
2. 在全屏播放器歌词右侧打开 **算法智能对齐**，选择要对齐的辅助轨道
3. 翻译对齐需先点击 **安装环境** 并等待就绪；只处理音译时无需安装
4. 点击 **开始对齐**，检查候选并逐行勾选，再点击 **应用勾选的行**
5. 应用后立即更新歌词显示；需要保留结果时，打开 **复制歌词 → 保存完整歌词**，预览更改并保存

默认保留已有完整对齐。需要重算时，勾选 **重新对齐已有逐字翻译和音译**；未选择或匹配不足的行保持原样。保存目标与覆盖行为见 [AI 功能中的保存说明](/ai#应用、显示与保存)。

## 对齐的两类任务

这里的对齐指两种不同的任务：

- **逐字音译对齐**：已有日语逐字歌词及其时间戳，把现成的罗马音匹配到每个原文片段，并继承时间戳。
- **逐字翻译对齐**：已有原文逐字时间戳，把现成的中文或英文翻译按语义匹配到原文对应片段，再生成翻译的逐字时间轴。

两者都只建立原文与辅助文本之间的映射关系，保留主歌词时间轴。以一行歌词为例：

| 主歌词（已有逐字时间戳） | 现有音译            | 现有翻译           |
| ------------------------ | ------------------- | ------------------ |
| 君 `10.00–10.40`         | `kimi to mita yume` | `与你一同看过的梦` |
| と `10.40–10.65`         |                     |                    |
| 見た `10.65–11.25`       |                     |                    |
| 夢 `11.25–12.00`         |                     |                    |

理想的输出是保留主时间轴，同时得到：

- 音译对齐：`kimi` `10.00–10.40`、`to` `10.40–10.65`、`mita` `10.65–11.25`、`yume` `11.25–12.00`
- 翻译对齐（语义短语）：`与你一同` `10.00–10.65`、`看过的` `10.65–11.25`、`梦` `11.25–12.00`

> 上例是为说明目标格式人工构造的示意，并非模型实际运行结果。

## 音译：读音匹配 + 编辑距离

不能直接用空格拆分音译后按下标对应——日语中一个汉字可能对应多个音拍，一段罗马音也可能跨越多个原文字符。例如 `今日` 读作 `kyou`，两个汉字不能各自分配一个罗马音单词。正确思路是先按语言学意义上的读音单元建立关联，再依据原文时间边界派生音译时间戳。

Sakura Player 的实现：

- [Kuromoji](https://github.com/takuyaa/kuromoji.js)（Apache-2.0，内含 IPADIC 词典）分析日语原文并生成候选读音；
- [WanaKana](https://github.com/WaniKani/WanaKana)（MIT）处理假名与罗马音转换，统一读音表示；
- 全局编辑距离匹配现成音译，整词允许横跨多个原文字词（如 `今` `日` 共同对应 `kyou`）。

原有大小写、空白和标点均由原文本切片保留，不会改写。主要面向日语罗马音；词典不支持或匹配分数不足的行保留原样。音译对齐不依赖 Python 环境，开箱即用。

## 翻译：跨语言词对齐 + 时间映射

翻译对齐使用 [SimAlign](https://github.com/cisnlp/simalign)（MIT）。它利用预训练多语言 BERT 的跨语言词向量相似度建立词对齐关系，不需要收集平行语料重新训练模型。

流程：逐字原文与已有时间戳 → 中文分词（运行时 ICU `Intl.Segmenter`，无需另装 jieba）→ SimAlign IterMax 匹配原文词与译文词 → 词索引映射回原词时间 → 跨语言重排与一对多映射合并为语义短语。

语义对齐不等于时间顺序对齐：日语与中文、英文之间可能存在语序变化、增译、省译，或多个原文词对应一个译文词。因此：

- 重排和一对多映射合并成语义短语，不按译文长度机械切分时间；
- 匹配评分只是筛选条件，分数不足（阈值 0.65）的行保留原有对齐，不强制编造时间戳；
- 算法只输出索引配对，文本原样保留，应用前可在预览中逐行检查。

## 运行环境

翻译对齐需要本地 Python 环境。点击对齐弹窗中的「安装环境」后，播放器自动完成便携 Python 下载、虚拟环境创建、依赖安装、模型下载与推理验证；打开弹窗本身不会触发安装。

- 便携解释器来自 [Python Standalone Builds](https://github.com/astral-sh/python-build-standalone)，固定 CPython 3.12.15，安装时校验长度与内置 SHA-256；
- 覆盖 Windows / macOS / Linux 的 x64 与 ARM64；Windows ARM64 使用 x64 解释器及依赖，需要系统支持 x64 应用；
- macOS 使用 PyTorch 2.2.2 与 NumPy 1.26.4 兼容 Intel Mac；Windows / Linux 从 PyTorch 官方 CPU 索引安装，不下载 CUDA 依赖；
- Windows 的 VC++ 运行库通过 `msvc-runtime` 安装到专用虚拟环境，不要求用户另行安装系统组件；
- 模型固定为 `google-bert/bert-base-multilingual-cased` 的指定版本，逐文件校验 SHA-256，采用 safetensors；
- 下载遵循播放器网络代理配置；模型准备完成后验证和对齐均离线执行。

文件统一存放于 `{userData}/app-data/runtimes/lyric-alignment/`，不读取系统 Python、不修改 PATH、不使用全局 Python 包或 Hugging Face 缓存。安装分阶段显示进度，可取消或失败重试；关闭弹窗后安装继续在后台进行，明确退出播放器会取消安装并等待清理。「卸载环境」可移除本功能的 Python、虚拟环境、模型和缓存；未安装环境时取消勾选翻译，仍可使用音译对齐。

## 使用与行为

- 只处理真实逐字主歌词，默认跳过已完整对齐和缺少辅助文本的轨道；勾选「重新对齐已有逐字翻译和音译」可重算所选辅助轨道；
- 预览中可逐行取消选择，匹配不足的行保留现有文本；
- 同时只运行一个任务，每次任务独占 worker 与 Python 子进程，结束后释放词典和模型；
- 输入限制为 1,000 行、合计 64,000 个字符；
- 应用后更新辅助轨道并同步外部歌词窗口，原文和主歌词时间戳保持不变；写入文件需另行保存；
- 模型加载或计算失败时，已成功的音译可单独应用，翻译原样保留。

## 设计取舍

- **不使用音频强制对齐**：不需要 Whisper、MFA 等模型重新识别音频，成本与准确率都不划算；
- **不使用 LLM 兜底**：对齐只做关联，低置信度内容宁可保留原样，交给预览中的人工修正；
- **不破坏已有歌词**：任何改写、越界或低分结果都会被拒绝，翻译和音译文本始终原样保留。

目前社区仍没有一个经过验证、能将任意逐行翻译和音译转换为高质量逐字时间轴的完整开源库；本功能在其基础上组合了读音匹配与跨语言词对齐，目标是音译尽量精确自动对齐、翻译按语义自动对齐，不可靠的部分标记出来由用户决定。

## 格式与许可证

- AMLL 的 TTML 格式支持逐字音译与逐字翻译数据，但 AMLL Player 对逐字翻译仍按逐行方式显示。本功能应用后复用现有辅助 TTML 保存路径，外部播放器若不支持逐字翻译会自动退化为逐行显示。
- 集成依赖的许可证需单独核对：SimAlign 为 MIT，Kuromoji 为 Apache-2.0（内含 IPADIC 词典），WanaKana 为 MIT，awesome-align 为 BSD-3-Clause，AMLL 主仓库为 AGPL-3.0，LDDC 为 GPL-3.0。本功能未复制 LDDC 或 AMLL 的源码，相关依赖的版权与许可证声明保留在各自发行包中。
