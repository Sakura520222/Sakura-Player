# 算法智能对齐

全屏播放器歌词右侧的「算法智能对齐」将已有翻译与音译关联到主歌词逐字时间轴。分词、读音匹配和语义推理由播放器自带的 **Rust 工作进程** 完成，无需安装 Python、PyTorch 或其他运行环境。

它只处理已有文本：不识别音频，不生成或改写歌词，不重建主歌词时间轴。AI 歌词翻译和模型配置是独立功能，见 [AI 歌词](/ai)。

## 使用方式

1. 加载具有真实逐字时间的主歌词，以及已有的翻译或音译
2. 打开「算法智能对齐」，选择翻译、音译或两者
3. 翻译首次使用时点击「下载或校验模型」；只处理音译时无需下载
4. 点击「开始对齐」，检查逐行预览，并勾选希望应用的候选行
5. 点击「应用勾选的行」立即更新歌词显示；需要写入文件时再显式保存歌词

默认保留已完整对齐的辅助轨道。「重新对齐已有逐字翻译和音译」允许重新计算上方选中的轨道；未选择、未匹配或未勾选的轨道保留原有内容。预览分别统计本次检查、匹配成功和已有对齐的数量。

只有整行时间、没有辅助文本或不足两个独立时间锚点的行不会生成逐字候选。匹配评分用于筛选，不表示正确率，应用前仍需检查预览。

## 音译匹配

- 日语通过 Lindera/IPADIC 获取词性、基本形和读音，使用原生 WanaKana 转换假名，再进行全局编辑距离及唯一读音锚点匹配
- 保留 IPADIC 的多读音顺序及同分优先级，支持已有注音、助词、长音、促音、转写体系差异和跨主歌词字词的整词读音
- 中文拼音通过多音字词典匹配，保留声调、大小写、标点和空白；不把 `u` 与 `ü` 混为一音
- 输出必须完整覆盖现成音译且满足评分要求，缺词、歧义或未知读音过多时保留原行

## 翻译匹配

翻译使用 Candle 在本机 CPU 运行固定的多语言 BERT，提取与原 SimAlign 相同的第八层词向量。Rust 实现余弦相似度、IterMax、子词与完整词候选、实词短语扩展和词典基本形候选，并保留原有候选优先级。

中文译文采用 ICU 同源词典和 ICU4C 的最小词频代价切分，避免更换分词实现后改变语义锚点。词对始终映射到主歌词原词范围；跨语言重排复用现有辅助时间轴顺排流程，不按译文字数制造时间。

翻译失败不会丢弃已经匹配成功的音译。相关错误可在弹窗中查看，原有翻译保持不变。

## 模型下载与移除

### 下载与存放位置

模型固定为 `google-bert/bert-base-multilingual-cased` 的 `3f076fdb1ab68d5b2880cb87a0886f315b8146f8` 版本，权重约 714 MB。下载遵循播放器代理设置，逐文件验证长度和 SHA-256；仅在原生推理验证成功后发布就绪标记。准备完成后的对齐完全离线执行。

打开弹窗或开始对齐不会自动下载。下载可取消、重试，关闭弹窗或主窗口后可继续后台运行；重新打开可恢复进度，明确退出播放器会取消并等待清理。

文件存放在 `{userData}/app-data/runtimes/lyric-alignment/`：

```text
lyric-alignment/
├── model/          # 固定版本的模型、分词器与许可证
└── ready.json      # 已通过原生推理的完成标记
```

点击「下载或校验模型」会先校验本地文件，完整文件直接复用，仅下载缺失或损坏的文件。验证失败可重试，已有完整模型文件不会重复下载。

### 移除模型

模型标记不绑定绝对目录或平台，便携版移动后无需重新下载模型。「移除模型」删除本功能的模型目录；移除后仍可使用音译，翻译需重新准备模型。对齐使用中、下载中或移除中会阻止并发操作。

## 资源与行为边界

- 同时只运行一个任务，每次任务独占 Rust 进程，结束或取消后回收词典、模型和计算线程
- 模型不常驻播放器主进程，计算不阻塞歌词动画与播放控制
- 输入上限为 1,000 行、合计 64,000 个 UTF-16 代码单元，单次进程输入输出各不超过 1 MiB
- 模型每侧最多 512 个子词，超长输入不接受截断后的伪完整结果
- 切歌、换源、修改歌词、关闭弹窗或取消任务会使旧结果失效
- 复用现有的辅助轨道开关、歌词窗口同步、TTML 和本地文件保存流程

原生工作进程与播放器一起构建，目标平台为 Windows、macOS、Linux 的 x64/ARM64。性能数据和实际验证范围见[原生对齐验证](/native#对齐验证)；模型文件本身与平台无关。
