# 主歌词声学对齐验证

验证日期：2026-11-16，Windows x64，CPU 执行 MMS_FA UINT8。这是实现验证和有限歌曲样本对照，不是跨语言准确率评测。

## 真实歌曲

用户提供三首本地歌曲，使用内嵌 KRC / TTML 的主歌词及其逐字时间作参考。只向声学引擎传入原文与行级时间，移除字级时间；不包含背景声部与歌曲信息行。候选字词按原文范围映射回参考字词，比较范围起止时间，不把参考中的汉字词组均分。

| 歌曲                                       | 语言   | 参考 | 候选 / 演唱行 | 起点平均差 | 起点 ±100 / ±200 / ±500 ms | 终点平均差 | 终点 ±100 / ±200 / ±500 ms |
| ------------------------------------------ | ------ | ---- | ------------- | ---------- | -------------------------- | ---------- | -------------------------- |
| 银河列车 — 宴宁                            | 普通话 | KRC  | 27 / 36       | 201 ms     | 26% / 49% / 100%           | 322 ms     | 14% / 32% / 84%            |
| 愛しさと感謝の気持ち — 榊原由依            | 日语   | KRC  | 37 / 47       | 175 ms     | 34% / 63% / 98%            | 369 ms     | 13% / 31% / 79%            |
| 唯有追赶风的方向 — 知更鸟、HOYO-MiX、Chevy | 英语   | TTML | 7 / 33        | 29 ms      | 100% / 100% / 100%         | 82 ms      | 73% / 96% / 100%           |

上表是初版启用评分筛选时的对照，现已按用户要求取消该生成限制。上述误差仅统计当时生成候选的行，参考文件未经过独立人工校准。候选比例不是正确率。

### 取消生成限制后的整曲结果

低评分、未知读音和长行均进入计算，质量问题改为警告。三首歌的主歌词全部返回，未跳过演唱行：

| 语言   | 返回 / 主歌词行 | 起点平均差 | 起点 ±100 / ±200 / ±500 ms | 终点平均差 | 终点 ±100 / ±200 / ±500 ms |
| ------ | --------------- | ---------- | -------------------------- | ---------- | -------------------------- |
| 普通话 | 36 / 36         | 194 ms     | 27% / 53% / 99%            | 311 ms     | 12% / 33% / 86%            |
| 日语   | 47 / 47         | 186 ms     | 33% / 61% / 97%            | 374 ms     | 12% / 29% / 77%            |
| 英语   | 33 / 33         | 223 ms     | 63% / 69% / 87%            | 254 ms     | 51% / 68% / 86%            |

这些数据统计全部输出候选。Debug 整曲耗时约 43、56、26 秒。全部返回不等于全部准确，低可信行和拖音结束边界仍需试听校正。

普通话、日语、英语分别有 9、10、26 行带质量警告。另将中文前 12 句合并成一条约 45.4 秒的长行，成功返回 134 个字词和长行提示，验证超过原 30 秒边界时仍能完成生成。

边界消融：不保留前后 500 ms 余量时，中文候选只有 5 / 36；保留余量后为 27 / 36，评分阈值不变。促音、拗音成组处理用于避免日语小假名被强制分配独立音频锚点。

AutoMix Demucs 对照覆盖三种语言的少量唱句及额外英文未匹配唱句。分离后的英文已匹配句评分提升，但两个选取的未匹配英文句仍不达门槛；中文句首失败需通过时间窗口余量解决。此次证据不足以把分离作为默认前置步骤。

另外使用 TorchAudio 官方中文 `clean_speech.wav` 验证 ONNX 输入、输出、字音映射与毫秒单位，生成 17 个字词候选。实现读取模型已输出的对数概率，不对带固定通配符的输出再次 softmax。

## 资源与回归

全量生成版中文整曲独立工作进程峰值工作集约 486 MiB，耗时约 33 秒，任务结束后进程退出。模型仅存在于子进程，取消等待子进程实际关闭后释放租约。PCM 按窗口推理，CTC 通过检查点限制回溯块大小，不常驻完整的帧乘字词矩阵。

隔离配置下，播放器启动 60 秒的既有 `app.getAppMetrics()` 日志：改动前 Browser / GPU / Network / Main Tab 为 157 / 112 / 58 / 119 MB，初版改动后为 158 / 111 / 58 / 115 MB，最终全量生成版为 182 / 142 / 95 / 126 MB。改动前 10 分钟采样为 157 / 111 / 58 / 113 MB。最终空闲启动样本高于基线；目前采样不足以判断是否存在持续增长，也不构成无泄漏结论。声学工作进程的峰值另行测量。

回归覆盖：重复 CTC 字符、跨检查点长行回溯、静音、无效矩阵、日语读音、原文与空白保留、拒绝越界和改字、低评分警告、已有逐字重算、1100 行自动批处理、显示均分替换、CUE 时间、切歌和取消、双模型租约、辅助轨道接续、TTML 往返和存储重载。

完整 Rust 测试中的既有 mBERT 实模型用例需设置 `SAKURA_ALIGNMENT_MODEL_DIR`，未设置时仍按原约定跳过。生产目标 Clippy 独立检查；`--all-targets` 的既有 `semantic.rs` 测试模块位置触发 `items_after_test_module`，不属于本次声学代码。

## 复现

先构建播放器原生模块及工作进程，再构建现有内存监测程序：

```bash
cargo build -p lyric-alignment --example measure
pnpm exec tsx scripts/benchmark-primary-alignment.ts samples.json <模型目录> <onnxruntime库文件> build/primary-alignment-benchmark
```

样本清单为 JSON 数组，每项包含 `name`、`source` 音频路径、`language`（`zh` / `ja` / `en`）。默认只读内嵌歌词，也可提供 `lyricPath` 和 `format` 使用外部参考。脚本输出请求、结果和摘要到指定报告目录，不修改音源。没有逐字参考的样本不能用于计算字词误差。

模型许可及出处见 `licenses/MMS-MODEL-NOTICE.txt`。验证不随仓库分发用户音频或歌词。
