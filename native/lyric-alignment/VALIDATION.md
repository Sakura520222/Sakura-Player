# 原生歌词对齐验证

验证日期：2026-10-19，实际执行平台为 Windows x64

## 回归与集成

- 221 组重写前实现的词典、读音匹配和语义范围用例通过原生回归
- 同一 mBERT 版本的 28 行最终语义结果与重写前一致，超过 512 子词时不能通过短语候选绕过长度限制
- JavaScript 与发布测试共 1,294 项通过，Rust 工作区 129 项通过；需要本地模型的测试另行显式执行并通过
- TypeScript、ESLint、Rust Clippy、格式检查、Electron 和文档构建通过
- 播放器内验证了模型准备、预览与应用、默认保留已有对齐、强制重对齐、关闭与取消、缺模型时单独使用音译、模型移除及播放控制响应
- Windows 工作进程静态链接 CRT，PE 导入检查仅包含 Windows 系统 DLL
- 静态 CRT 发行版本完整重放 114 首有效音乐，输出与已验证的原生结果零差异

## 真实音乐语料

递归检查 240 首音乐，234 首有内嵌歌词，119 首保存有独立辅助轨道。114 首满足对齐条件，强制重对齐覆盖 4,232 行：4,197 行翻译、3,482 行音译。其余 120 首缺少可处理的逐字主歌词或辅助文本，6 首无歌词

生成 4,014 行可靠翻译候选和 3,358 行可靠音译候选，主界面逐轨校验无拒绝。112 首产生候选并通过实际应用轨道的保存重读检查；另外 2 首没有可靠候选，保留原有内容。原文、主时间轴和注音在应用阶段保持不变

90 首含音译曲目的 3,492 个输入行与旧实现逐行对照，最终文本切片和原词范围零差异。所有 240 首原文件的 SHA-256、文件大小及修改时间均核对一致

原有格式转换会对 6 首的部分未重对齐空白或背景句作表示归一化，未重对齐的对照导出也有相同现象；实际应用的原生轨道已独立逐片验证。该项不计为新增对齐效果或语义准确率

## 性能验证方式

固定 28 行翻译和 71 行音译语料，各启动三次独立进程，使用相同模型及 2 个 CPU 推理线程。记录进程树峰值工作集；Windows 另读取根进程的系统峰值，避免遗漏短任务

开发者可按 README 的命令重现。详细音乐库文件名、输入输出及本机性能原始数据保留在工作区 `build/native-alignment-baseline/`，不作为发行资源打包

本机三次独立进程的中位数：28 行翻译从 30.214 秒降至 3.982 秒，峰值工作集从 868.0 MiB 降至 619.8 MiB；71 行音译从 0.956 秒降至 0.253 秒，峰值工作集从 481.9 MiB 降至 42.6 MiB。新版本测量对象为实际发行的静态 CRT 工作进程

## 平台边界

构建支持 Windows、macOS、Linux 的 x64/ARM64。此次未在其余五个平台实际运行，不能将 Windows 结果当作六平台运行验证。匹配覆盖率是现有可靠性门槛下的候选比例，不代表人工语义正确率
